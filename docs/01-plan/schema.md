# 데이터 스키마

## 범위

초기 MVP는 계정과 서버 없이 한 브라우저에서 동작한다. 따라서 데이터베이스 테이블 대신 localStorage에 JSON 배열로 저장한다. 이후 동기화를 도입하더라도 아래 엔티티와 필드 이름을 기준으로 확장한다.

## 엔티티

- `Transaction`: 사용자가 기록한 한 건의 수입 또는 지출
- `Category`: 내역을 분류하는 표시용 값. MVP에서는 고정 목록이며 별도 엔티티로 저장하지 않는다.

## Transaction 필드

| 필드 | 타입 | 필수 | 제약 | 설명 |
|---|---|---:|---|---|
| `id` | UUID 문자열 | 예 | 고유 | 내역 식별자 |
| `type` | enum | 예 | `income`, `expense` | 수입 또는 지출 |
| `amount` | 양의 정수 | 예 | `> 0` | 원 단위 금액 |
| `date` | `YYYY-MM-DD` | 예 | 유효한 날짜 | 실제 거래일 |
| `category` | 문자열 | 예 | 제공된 카테고리 중 하나 | 분류 |
| `memo` | 문자열 | 아니오 | 최대 80자 | 사용자가 남기는 메모 |
| `createdAt` | ISO 8601 문자열 | 예 | 자동 생성 | 기록 생성 시각 |

## 검증 규칙

1. 금액은 1원 이상의 정수만 저장한다.
2. 내역 종류는 수입과 지출 중 하나여야 한다.
3. 날짜와 카테고리는 비어 있을 수 없다.
4. 메모는 화면 출력 전에 HTML 이스케이프한다.
5. 삭제는 현재 MVP에서 영구 삭제이며, 서버 동기화 단계에서는 `deletedAt`을 검토한다.
